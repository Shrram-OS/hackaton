# Симулятор токамака — набір учасника

Тут усе в одному виконуваному файлі: фізика установки, вимірювальні прилади,
генератор датасетів і залік вашої моделі. Працювати з ним ви будете у
браузері.

## Запустити

У наборі два файли під різні системи:

| файл | для чого |
|---|---|
| `toksym` | macOS (і Apple Silicon, і Intel) |
| `toksym-linux` | Linux x86-64, **у тому числі WSL на Windows** |

Розпакуйте архів і відкрийте теку в терміналі. Це єдине місце, де термінал
потрібен — далі все у вікні браузера.

**macOS.** Файл не підписаний, тож система спершу відмовиться його запускати.
Знімається так:

    xattr -d com.apple.quarantine ./toksym
    chmod +x ./toksym
    ./toksym

**Linux і WSL:**

    chmod +x ./toksym-linux
    ./toksym-linux

Відкриється браузер — одразу на симуляції. Якщо не відкрився сам, адреса
надрукована в терміналі: `http://127.0.0.1:7373/`. Зупинити — Ctrl+C у тому ж
терміналі.

**Окремо про WSL.** Браузер там на боці Windows, тож програма пробує відкрити
його через `wslview`, а якщо того немає — через `explorer.exe`. Якщо не
відкрився, просто вставте `http://127.0.0.1:7373/` у звичайний браузер
Windows: WSL2 пропускає localhost у обидва боки.

Далі в README `./toksym` означає той файл, який підходить вашій системі.

Файли, які програма пише, лягають у ту теку, з якої ви її запустили.

## Що є в інтерфейсі

Угорі праворуч дві кнопки:

* **⛁ Dataset** — зібрати собі дані для навчання;
* **⏱ Test run** — прогнати свою модель і подивитися, що вийшло.

Решта екрана — сам імпульс: рівновага, графіки, профілі. Кнопка **Start**
запускає відтворення.

## Датасет

**⛁ Dataset** → *Source: Generate new runs* → скільки розрядів (**Runs**),
з якого числа їх розігрувати (**Master seed**) → **Generate**.

Коли скінчиться, з'являться дві кнопки завантаження.

`measured.csv` — сто вимірюваних каналів на кожен крок 5 мс. Це рівно те, що
модель отримає на заліку: жодної зайвої колонки, жодної відсутньої. Порожня
клітинка означає, що прилад на цьому кроці відмовив.

`shots.csv` — по рядку на розряд: сценарій, чи зірвався, і коли саме сталося
термічне гасіння. Мітки лежать окремо навмисно: так вони не потрапляють у
жоден рядок часових рядів.

Під полями — **Output columns**. Сто вимірюваних каналів там завжди; галочки
нижче додають колонки зі справжнім станом машини, для власних досліджень.

**Sample every** проріджує запис: фізика однаково йде кроком 5 мс, але у файл
піде кожен n-й рядок. Беріть кожен, поки файл не став завеликим.

⚠️ На заліку модель отримує **тільки** вимірювані канали. Усе, чого вона
навчилася з істини, має бути відновлюване з приладів — інакше на прогоні
воно не спрацює.

**Master seed** — те єдине число, з якого відтворюється весь набір. Той самий
сід дає ті самі розряди, інший — інші. Запишіть його, якщо захочете
повторити.

## Модель

Клас із двома методами:

```python
class Model:
    def start_shot(self, meta):          # новий розряд
        ...
    def predict(self, t, channels):      # ймовірність зриву, 0…1
        return 0.0
```

`channels` — словник «ім'я каналу → число». Канал має право відмовити: тоді
значення буде `nan`. Історію збирає сама модель: повернутися до попереднього
кроку не можна.

У кінець файлу допишіть:

```python
if __name__ == "__main__":
    from toksym_model import serve
    serve(Model())
```

### Ваги

Модель має приїхати **навченою**. Зберігайте ваги поруч зі скриптом і
вантажте відносним шляхом:

```python
import json

with open("weights.json") as f:
    W = json.load(f)
```

Це просто працює — і для `json`, і для `pickle`, і для `joblib`: модель
запускається з тієї теки, де лежить.

### Що саме здавати

Здача — це **тека**:

```
моя-здача/
  toksym.json     маніфест: що запускати і без чого воно не працює
  model.py        ваш скрипт
  weights.json    навчені ваги (назва будь-яка)
```

`toksym.json`:

```json
{
  "schema": 1,
  "entry": "model.py",
  "files": ["weights.json"],
  "requires": ["numpy"],
  "name": "необов'язковий підпис",
  "notes": "необов'язкова нотатка; потрапляє у звіт"
}
```

Обов'язкові поля — `schema`, `entry`, `files`. Усі шляхи — відносно теки, де
лежить сам маніфест. `files` може бути порожнім списком, але написати його
треба: це явна заява «моїй моделі більше нічого не потрібно».

Обгортку `toksym_model.py` надсилати не треба — вона додається сама.

Готовий взірець — тека `examples/submission/`.

## Перевірити модель

**⏱ Test run** → перетягніть теку здачі у велику зону (або клацніть по ній і
оберіть теку).

Під зоною одразу з'явиться, що саме приїхало: точка входу, скільки файлів,
ваші підпис і нотатка. Якщо щось не так — червоний список, а кнопка **Run
model** лишиться сірою.

**Перевірка сувора.** Прогін не почнеться, якщо немає `toksym.json`, він не
розбирається, `entry` не вказує на наявний файл `.py`, якогось файлу зі
`files` немає або він порожній, чи якоїсь бібліотеки зі `requires` не
встановлено. Програма назве **всі** проблеми одразу, а не першу-ліпшу.

Якщо `toksym.json` немає зовсім, програма покаже готовий текст — лишиться
зберегти його у файл.

Розряди завжди одні й ті самі — двісті, однакові для всіх. Міняти їх не
можна навмисно: порівнювати два прогони на різних розрядах безглуздо. На ста
розрядах розкид між вибірками сягає ±25 пунктів, а різниця між моделями
зазвичай менша.

Два поля — ваші:

| поле | що це |
|---|---|
| **Lead time, s** | наскільки завчасно має спрацювати тривога |
| **False-alarm budget** | яку частку хибних тривог ви готові терпіти |

**Run model** — і далі видно поступ.

### Що показує звіт

Угорі — чотири плитки: скільки зривів спіймано вчасно, скільки хибних
тривог, який вийшов поріг, медіанне випередження.

Нижче — кожен розряд окремим рядком на спільній часовій осі. Колір каже, чим
усе скінчилося:

| | |
|---|---|
| **Caught** | тривога за потрібний час до гасіння |
| **Late** | тривога була, але вже надто близько |
| **Missed** | зрив із прекурсором, тривоги не було |
| **False alarm** | тривога на розряді, який дійшов до кінця |
| **Quiet** | нічого не сталося, тривоги не було |
| **Excluded** | спонтанний зрив або контакт зі стінкою: передбачати нема чого |

Агрегат каже, скільки пропущено; рядки кажуть, ЧОМУ саме. По легенді можна
клацати, щоб сховати зайве.

### Забрати дані прогону

Після заліку з'являться дві кнопки:

* `measured.csv` — сто каналів, які бачила модель, плюс колонка `p`: що саме
  вона відповіла на кожному кроці;
* `shots.csv` — по рядку на розряд: мітки, момент тривоги й вирок.

Колонка `p` — єдине, чого не дістати інакше. Самі розряди повторюються з того
ж сіда, а от повний слід відповідей лишається тільки тут: у звіті
зберігаються лише моменти, коли ймовірність брала новий максимум. Саме за
цією колонкою видно, чи модель нічого не помітила, чи помітила й не дотягнула
до порога.

### Якщо модель не стартує

В інтерфейсі буде її власний traceback — читайте його, він каже рівно те, що
сталося. Найчастіша причина першого разу — буферизація виводу: після друку
відповіді потрібен `flush`.

## Приклади

У теці `examples/`:

* `model_quiet.py` — ніколи не б'є тривогу. Підлога: будь-яка метрика, яка не
  відрізняє від неї справжню модель, виміряна неправильно.
* `model_fgw.py` — рахує частку гринвальдівської межі за підручником. Один
  канал, одна формула.
* `model_baseline.py` — два прилади, згладжування, жодного навчання. З неї
  варто почати: у докстрінгу розписано, звідки взялися пороги, який канал
  довелося прибрати після вимірювань і чому одне число на одному сіді нічого
  не доводить.
* `submission/` — та сама модель, зібрана як повна здача. Перетягніть її в
  **Test run**, щоб побачити, як усе має виглядати.

## Що вибирати самому

Наскільки завчасно має спрацювати тривога і скільки хибних тривог
припустимо — вирішуєте ви, полями **Lead time** і **False-alarm budget**.

Це частина задачі: знайти робочу точку й обґрунтувати, чому саме вона.
Тривога за 10 мс до гасіння нікого не рятує; бюджет хибних тривог 30 % на
установці означає зупинений експеримент.

## Правила заліку

| Що сталося з моделлю | Чим скінчиться |
|---|---|
| Не стартувала або не сказала `ready` за 30 с | прогін зупинено |
| Завмерла більш як на 1 с на кроці | прогін зупинено |
| Впала посеред прогону | прогін зупинено |
| Відповіла не числом | прогін зупинено |

`NaN` від моделі вважається нулем, вихід за межі `[0, 1]` обрізається.

У звіт пишеться, скільки тривав крок моделі: p50, p99 і скільки кроків не
вклалися в 5 мс. На установці між кроками саме стільки.

## Про чесність

Фінальний залік іде на розрядах, породжених збіркою організатора після
дедлайну. У ній вкомпільований секрет, тож той самий номер розряду дає інші
розряди, ніж у вашій копії. Підібрати його не можна.

Вимірювальний тракт відкритий навмисно: у реальній установці характеристики
приладів теж відомі. Задача не в тому, щоб угадати шум.

# Додаток: те саме в терміналі

Усе вище доступне й командами — якщо вам так зручніше або треба в скрипт.
Повна довідка: `./toksym --help`.

| команда | що робить |
|---|---|
| `./toksym` | підняти інтерфейс |
| `./toksym gen --shots 200 --seed 1 --out mydata` | датасет |
| `./toksym check моя-здача` | перевірити здачу, нічого не запускаючи |
| `./toksym score --submission моя-здача --shots 200 --seed 1` | прогнати здачу на своїх розрядах |
| `./toksym rescore run.json --lead 0.3` | перерахувати звіт під інший запас часу |

Корисні ключі до `score`: `--lead` і `--budget` (те саме, що поля в
інтерфейсі), `--report ФАЙЛ` (зберегти звіт), `--save-data КАТАЛОГ` (дані
прогону).

## Протокол, якщо ви пишете не на Python

Обгортка `toksym_model.py` — для Python. Під нею простий обмін: один рядок
JSON униз, одне число вгору, суворо по черзі.

```
→  {"type":"hello","protocol":1,"dt":0.005,"n_shots":400}
←  {"type":"ready"}
→  {"type":"shot_start","shot_id":0,"duration":16.42,...,"channels":[...]}
→  {"type":"step","t":0.005,"v":[...сто чисел, null = відмова приладу...]}
←  0.0123
→  {"type":"shot_end","shot_id":0}
→  {"type":"bye"}
```

Рядок, що починається з `#`, вважається логом і не є відповіддю — друкуйте
ним усе, що хочете бачити під час прогону.

Після кожної відповіді потрібен flush, інакше залік побачить мовчання.

У маніфесті вкажіть свій запуск через `entry` і `requires`; якщо модель
взагалі не на Python, скористайтеся командним рядком:
`./toksym score --shots 200 --seed 1 -- ./моя-модель`.
